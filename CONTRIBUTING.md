# Contributing to Dashboard App

Thank you for contributing to the Dashboard App. Please follow these guidelines when making changes.

## 1. Branch Naming

Create a separate branch for each task. Use a clear prefix and task description.

Examples:
- `feature/t1-5-contributing-guide`
- `fix/invoice-validation`
- `docs/update-readme`

Do not work directly on the `main` branch.

## 2. Commit Message Style

Write short, clear commit messages that describe the change.

Examples:
- `Add pull request template`
- `Fix invoice validation`
- `Update project documentation`

Keep commits focused on one logical change.

## 3. Pull Request Rules

1. Create a GitHub Issue before starting a task.
2. Create a branch from `main`.
3. Make small, focused commits.
4. Open a Pull Request to merge changes into `main`.
5. Link the related issue using `Closes #<issue-number>`.
6. Request a review from your review partner.
7. Address review comments before merging.
8. Wait for required checks and approval.
9. Use squash merging when merging a Pull Request.

Do not merge your own Pull Request without the required review and approval.

## 4. Definition of Ready

A task is ready to start when:
- The requirement is clear.
- Acceptance criteria are understood.
- Dependencies and questions are identified.
- The task has an estimate.

## 5. Definition of Done

A task is done when:
- The implementation meets the acceptance criteria.
- Relevant tests pass.
- No known errors or warnings introduced by the change remain unresolved.
- Documentation is updated when needed.
- The Pull Request has the required approval.
- All required checks pass.
- The Pull Request is merged.
- Actual hours are recorded and the issue is closed.

## 6. Testing

Test your changes before opening a Pull Request. Include clear testing steps in the Pull Request description. Add screenshots when the user interface changes.

## 7. Communication

Share progress during stand-ups:
- What you completed.
- What you plan to do next.
- Any blockers.

If you are blocked for more than 30 minutes, document what you learned in `docs/til/` and ask for help.
